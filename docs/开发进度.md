## 关键决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | 整体采用「保守方案」，不做过度建模 | MVP 优先跑通核心链路 |
| 2 | 否决 String → Prisma enum | SQLite 连接器不支持 Prisma enum |
| 3 | Prisma 降级到 6.19.3 | Prisma 7 的 `datasource.url` 破坏性变更对 MVP 零收益 |
| 4 | 专家状态不落库 | 瞬态数据，只走内存 + SSE，避免双真相源 |
| 5 | 共识必须追溯来源 | 反幻觉可测试性的硬前提 |
| 6 | summary 单一真相源 | 共识点只存 ConsensusItem，总结只存 Discussion.summary |
| 7 | 嘉宾生成走同步接口，不用 SSE | 一次性调用无真实事件流，前端 loading 态解决等待 |
| 8 | 立场多样性是 prompt 硬要求 | 覆盖争议维度 + 禁止中立套话；代码只校验结构 |
| 9 | 颜色重复自动修复、非法抛错 | 重复是模型小瑕疵可修，非法是数据完整性问题 |
| 10 | LLM 重试 1 次、超时 60s | 平衡鲁棒性与等待成本，超时不重试 |
| 11 | SSE history 不存 `speech_chunk` | `speech_end` 已带完整 message，重连无需逐块补课，避免 buffer 膨胀 |
| 12 | `start` 用 DB 原子条件更新抢占 | 先查后改存在并发窗口；内存 `activeRuns` 只作第二道保险 |
| 13 | 重启时把 `ongoing` 收敛为 `finished` | 编排状态在内存，重启后不可恢复，避免状态永久卡死 |
| 14 | SSE 服务端结束后不断连 | 避免 EventSource 自动重连风暴；由前端收到 `discussion_finished` 主动 close |
| 15 | `applyEvent` 做成纯 reducer | 与 React / 网络解耦，可直接单测；深冻结测试保证不修改入参 |
| 16 | transcript 按 `message.id` 去重 | 重连全量回放会重复推 `speech_end` |
| 17 | 前端测试用 vitest 2.1.9 | vitest 5 要求 Vite ≥ 6.4，项目是 Vite 5 |

## 技术约束（实现时必须遵守）

1. **Prisma 不要升回 7**，否则报 `P1012 datasource.url` 错误
2. **嘉宾状态**走 `Map<discussionId, Map<memberId, RuntimeState>>` 内存态 + SSE `status_update`
3. **轮次节奏**：主持人开轮（`Round.status=open`）→ 专家发言挂 `roundId` → 关轮时触发一次共识提炼
4. **共识溯源必写**：创建 `ConsensusItem` 时必须同时写 `ConsensusItemMessage` join 行
5. **字符串枚举用 Zod 校验**：`waiting/generating/ongoing/finished`、`speech/internal/summary`、
   `consensus/divergence`、`open/closed`、`host/expert`
6. **`Message.roundId` 可空**：开场前发言允许为 null
7. **SSE 事件 `id` 为讨论内自增**；history 不存 chunk，上限 500 条；finished 后 15 分钟清理
8. **`start` 必须原子抢占**：`updateMany({ where: { id, status: 'waiting' } })`，禁止先查后改
9. **前端收到 `discussion_finished` 后主动 `EventSource.close()`**（服务端不断连）
10. **HTTP 请求体必须是 UTF-8 JSON**：Windows 下用 curl 传中文请用 `--data-binary @utf8.json`，
    不要用控制台直接 `-d '中文'`（会按 GBK 发送导致乱码）
11. **前端状态变更只走 `applyEvent`**：禁止在其中读 `Date.now` / `Math.random` 或发请求
12. **transcript 必须按 `message.id` 去重**，consensus 按 `item.id` 合并，保证回放幂等
